Docker sandbox: why execution failed

The original errors
cat: probe.txt: Permission denied
available containment (rlimit) is below the required docker


These were connected. Docker failed its workspace probe, so automatic detection found only rlimit. The
production policy correctly refused the weaker tier.

Ownership mismatch
Python creates temporary work directories with permission mode 0700. Only the directory’s owner can
access them. The backend owned the directory, but the runner image used UID/GID 65532:65532.

If those user IDs differ, the runner cannot enter the mounted directory. Source files can also become
unreadable under a restrictive umask. The compiler needs permission to create its executable there, not
just read a probe.

The secure fix
    A non-root Linux backend runs the container with its effective UID and GID, explicitly using --user
      UID:GID.
    A root backend hands private workdirs and source/probe files to runner UID/GID 65532. Student
      code never runs as root.
    Workdirs stay private at 0700. Source and probe files use 0600. We did not make them world-
      writable.
    A random-token probe checks container reads, compiler-step writes, and whether the backend
      sees the written result.

Host paths must mean the same directory
A backend container and the host Docker daemon can have different filesystems. A Linux systemd
service using PrivateTmp=true also has a private /tmp. A bind source is interpreted by the daemon, not
by the client process.

The optional shared workspace settings handle this distinction. The provided systemd unit was updated
to use /run/trace-tutor-work, but your actual PM2 deployment does not use that unit.

Docker containment remains enforced: no container network, dropped capabilities, no-new-privileges,
resource caps, and read-only mounts/root during program execution.

Deployment: workspace, .env and restart

Prepare the shared workspace on Ubuntu
mkdir -p /srv/trace-tutor/sandbox-work
chmod 700 /srv/trace-tutor/sandbox-work
cd /srv/trace-tutor/backend
nano .env


mkdir -p creates the directory if needed. chmod 700 lets its owner read, write and enter it, while
denying access to other users. nano opens the deployment configuration.

Final sandbox configuration
Add or update each key once; avoid duplicate entries. Leave unrelated settings intact.
CODE_SANDBOX=docker
CODE_SANDBOX_REQUIRED=1
CODE_SANDBOX_MIN_TIER=docker
CODE_SANDBOX_MOUNT_STYLE=volume
CODE_SANDBOX_WORKDIR_ROOT=/srv/trace-tutor/sandbox-work
CODE_SANDBOX_HOST_WORKDIR_ROOT=/srv/trace-tutor/sandbox-work


docker selects the container runner. REQUIRED=1 enforces containment, MIN_TIER=docker rejects
rlimit, and volume selects syntax allowed by your wrapper. Both roots point to the same existing
directory on this host deployment.

Save in nano
An asterisk beside .env means changes are unsaved. Press Ctrl+O, Enter to write the file, then Ctrl+X to
exit. Alt+/ moves to the end of the file. Saving a file does not restart an already-running backend.

Profile picture: production media serving

The symptom and likely cause
Your uploaded avatar displayed a broken-image icon and the name text. The application generated an
avatar URL, but the browser could not load the image. We inspected avatar generation, MEDIA_ROOT,
MEDIA_URL, the media route and the serving flag.

The code defaults SERVE_MEDIA to DEBUG. Your server has DEBUG=0, so Django’s media view returns
404 unless SERVE_MEDIA=1 or another file server serves /media/. That was the likely cause; the actual
image HTTP response was not captured.

The configuration change
cd /srv/trace-tutor/backend
nano .env


Add or update:
SERVE_MEDIA=1


Save with Ctrl+O, Enter, exit with Ctrl+X, then restart:
pm2 restart trace-tutor --update-env


Refresh the live page with Ctrl+Shift+R. This configuration permits the existing media route to serve
uploaded files under backend/media/. No avatar code changes or image deletion were needed.

What remains to verify
The last screenshot showed SERVE_MEDIA=1 in nano with an unsaved marker. We confirmed the line
was correct and instructed you to save and restart, but no subsequent screenshot confirms that the
avatar loaded.

If it still fails, open the image in a new tab and note the URL and HTTP/error result. An incorrect URL,
missing file, file permissions, or nginx handling can also cause broken images. Do not assume that re-
uploading alone fixes a serving configuration problem.

Configuration safety
Keep DEBUG=0 in production. Serving avatars does not require turning on Django debug mode.
Your .env screenshots exposed credentials; arrange rotation with the server owner. This learning
document intentionally does not copy those secret values.

Your reusable checklist and command glossary

Repeat this workflow for a future fix
      Inspect the symptom and logs. Decide whether the cause is application code, environment
        configuration, file permissions, or deployment.
      Make the smallest relevant local change. Run appropriate checks and preserve evidence of the
        result.
      Confirm the target machine. Upload only the intended changed files; do not replace the
        server .env with your laptop .env.
      Save configuration changes. Check the service’s Python environment, workspace path, and current
        user permissions.
      Restart the correct deployed process. For this server, use PM2/Waitress, not manage.py runserver
        or the optional trace-tutor systemd unit.
      Verify server health and the actual browser action. A process being online is not proof that every
        feature works.

Useful server commands
pm2 list
pm2 logs trace-tutor --lines 50 --nostream
command -v docker
id
ls -ld /srv/trace-tutor/sandbox-work


These are reference commands for future diagnosis; they are not all shown executed on your server
during this session. The Docker command should resolve through your user shim, which uses the locked
wrapper.

 Term                          Meaning

 UID / GID                     Numeric user/group IDs used to evaluate Linux file access.

 Bind mount                    A host directory exposed at a path such as /work in a container.

 Docker versus rlimit          Docker isolates network/filesystem; rlimit primarily caps resources.

 Probe versus execution        A probe checks readiness; the live Run Code action confirms the full feature.

 Build versus restart          A frontend build creates assets; a backend restart reloads Python/configuration.
